04 Controls And Input

Status: partial

Spec

Keyboard, touch, and gamepad are all first-class v1 inputs. All input paths feed the same gameplay intent layer so rules, physics, tutorials, and tests do not depend on device-specific branches.

Input actions

The action layer exposes left flipper, right flipper, plunger charge, plunger release, nudge left, nudge right, nudge up, start, pause, restart, menu confirm, menu back, and view toggle if a future slice adds inspection camera support.

Keyboard controls

Keyboard defaults should be playable on common desktop layouts: left and right flippers on opposite hands, plunger on a hold/release key, nudges on nearby directional keys, and pause/restart separated from active play controls.

Touch controls

Touch controls provide large left and right flipper regions, an analog plunger drag or hold control, and explicit nudge controls. Touch UI must not cover the lower flipper area or the ball path.

Gamepad controls

Gamepad controls map flippers to shoulder or trigger inputs, plunger to an analog trigger or hold/release button, nudges to stick or d-pad, and pause/restart to standard menu buttons.

Input buffering

Flipper and plunger input must be responsive on the next simulation tick. The game should not lose quick taps during frame drops.

Focus and browser behavior

The game prevents browser scrolling or focus loss from active play controls where safe. Menus remain keyboard accessible and do not trap input after closing.

Control reminders

The start state shows concise device-aware controls. During play, reminders are hidden unless paused or the player has not launched the first ball.
