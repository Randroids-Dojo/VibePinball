08 State And Leaderboard

Status: not_started

Spec

VibePinball persists local preferences and eligible scores, then submits completed games to a global leaderboard with server-side sanity checks. The game must remain playable when online services are unavailable.

Local settings

Audio levels, input preferences, initials, accessibility choices, and last-used options persist through Vibekit storage helpers with Zod validation.

Session state

Active game state tracks score, ball number, active balls, tilt state, lock progress, multiball state, bonus counters, run start time, and table id.

Local high scores

The game stores a local high-score list so score chasing works offline and before leaderboard setup is complete.

Leaderboard submit

Completed games can submit score, initials, table id, duration, ball count, tilt count, multiball count, jackpot count, major scoring counters, and build version to the server.

Leaderboard sanity checks

The server rejects impossible or malformed score summaries, including negative values, invalid initials, wrong table id, impossible duration, impossible ball count, and counters inconsistent with the ruleset.

Leaderboard rate limit

Server routes use Vibekit server rate-limit helpers or equivalent Upstash-backed primitives to limit repeated submissions and protect the project-specific backing store.

Leaderboard storage

The global leaderboard uses a dedicated Upstash Redis resource attached only to the VibePinball Vercel project. It must not share another project's store.

Offline degrade

If the leaderboard service is unavailable, the game keeps local play, local scores, and clear non-blocking UI feedback. Failed submissions must not crash or erase a completed run.
