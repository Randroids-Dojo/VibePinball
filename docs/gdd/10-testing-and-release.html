10 Testing And Release

Status: partial

Spec

VibePinball needs both mechanical verification and qualitative playtest gates. The project cannot stop because requirements are technically present if the table is not fun, readable, and fair.

Unit tests

Pure scoring, rules, tilt, bonus, input mapping, storage schema, and leaderboard validation logic must have Vitest coverage.

Physics tests

Physics tests or deterministic harnesses should verify flipper activation, drain detection, sensor events, plunger launch ranges, nudge accumulation, and multiball ball accounting where feasible.

Render smoke

Playwright must verify that the 3D canvas renders nonblank pixels, the table is framed, the ball is visible after launch, and resize behavior does not hide the playfield.

Input smoke

Automated or manual smoke checks must cover keyboard, touch emulation, and gamepad mapping where browser automation allows it.

Leaderboard tests

API route tests must cover valid submission, invalid schema, impossible score summary, rate-limit behavior, unavailable KV, and leaderboard read response shape.

Release playtest

A release candidate must complete the playtest gate in docs/PLAYTEST.html: 3-5 minute target sessions, readable ball motion, reachable multiball, fair drains, useful nudging, and no blocking browser issues.

Fun factor audit

When GDD coverage reaches 80 percent, run docs/FUN_FACTOR_AUDIT.html and convert P0 or P1 gaps into release-blocking followups or dots.
